# محضر طاولة النماذج: تطبيق المهام التجريبي

### أنت

صمّموا تطبيق Flutter بسيط لقائمة المهام باللغة العربية: إضافة مهمة، وتعليمها كمكتملة، وحذفها، وحفظ المهام على الجهاز. واجهة واحدة نظيفة بتصميم Material 3. اجعلوه بسيطاً جداً لأنه أول اختبار للبناء، واستخدموا حزمة shared_preferences فقط.

### Claude (anthropic/claude-sonnet-5.5)

# خطتي كمهندس منظّم

بما أنه أول اختبار للبناء، أقترح **ملفاً واحداً `main.dart`** بلا هيكلة مجلدات معقدة، مع فصل منطقي واضح داخله.

## القرارات المعمارية

1. **إدارة الحالة:** `StatefulWidget` مع `setState` فقط. لا Provider ولا Riverpod، لأن حزمة واحدة مسموحة (`shared_preferences`).
2. **النموذج:** كلاس `Task` فيه `id` و`title` و`done`، مع `toJson` و`fromJson`.
3. **التخزين:** قائمة المهام كلها تُحفظ كنص JSON واحد تحت مفتاح واحد (`tasks`). هذا أبسط من تخزين حقول متفرقة، ويستخدم `dart:convert` المضمّنة دون أي حزمة إضافية.
4. **المعرّف:** `DateTime.now().microsecondsSinceEpoch.toString()`، دون حزمة `uuid`.
5. **الاتجاه العربي:** نضبط `locale: Locale('ar')`، ونلفّ الواجهة بـ `Directionality(textDirection: TextDirection.rtl)`. هذا يعمل دون `flutter_localizations`، لكن ستظهر الحوارات والأدوات النظامية بالإنجليزية. التطبيق لا يستخدم أياً منها، فالحل كافٍ.
6. **الواجهة:** `useMaterial3: true` مع `ColorScheme.fromSeed`، وشاشة واحدة فيها:
   - `Scaffold` مع `AppBar`.
   - حقل إدخال `TextField` وزر إضافة في أعلى القائمة، ويدعم الإضافة بالضغط على Enter.
   - `ListView.builder` تعرض `Dismissible` أو زر حذف صريح.
   - حالة فارغة برسالة "لا توجد مهام بعد".

## نقاط تنفيذ مهمة

- **التحميل:** استدعاء `_load()` في `initState`، مع مؤشر تحميل قصير حتى تُقرأ البيانات، حتى لا تومض الشاشة الفارغة.
- **الحفظ:** دالة `_save()` تُستدعى بعد كل تعديل (إضافة، تبديل، حذف).
- **التحقق:** تجاهل النص الفارغ بعد `trim()`.
- **تأكيد الحذف:** أفضّل زر حذف مباشراً مع `SnackBar` فيه "تراجع" بدل حوار تأكيد. هذا أسرع وأنظف، لكنه اختياري إذا أردنا تقليل الكود.
- **الإكمال:** `Checkbox` مع تسطير النص (`TextDecoration.lineThrough`) ولون خافت للمهمة المكتملة.

### ChatGPT (openai/gpt-6.1-sol)

أقترح تنفيذ نسخة صغيرة جداً، بلا طبقات أو حزم إضافية:

- **البنية:** ملف `main.dart` واحد، وشاشة `StatefulWidget` تدير قائمة المهام. نموذج المهمة يحتوي `id` و`title` و`isCompleted`.
- **الواجهة:** Material 3، واتجاه عربي `RTL` صراحةً، وعنوان «مهامي». حقل «أضف مهمة» وزر إضافة، ثم قائمة تعرض مربع إكمال ونص المهمة وزر حذف. المهمة المكتملة يظهر نصها مشطوباً.
- **التخزين:** تحويل القائمة إلى JSON باستخدام `dart:convert`، وحفظها تحت مفتاح واحد في `shared_preferences`؛ لا نحتاج أي حزمة أخرى.

**تفاصيل صغيرة مهمة للتجربة:**
1. إزالة الفراغات ورفض المهمة الفارغة، مع دعم الإضافة من زر لوحة المفاتيح.
2. عرض «لا توجد مهام بعد» حين تكون القائمة فارغة.
3. انتظار قراءة التخزين قبل السماح بالتعديل، كي لا تستبدل البيانات المحفوظة بالخطأ.
4. حفظ القائمة بعد الإضافة والإكمال والحذف، مع تسلسل عمليات الحفظ لتجنب كتابة نسخة قديمة فوق الأحدث.
5. إذا فشلت القراءة أو الكتابة، لا ينهار التطبيق؛ تظهر رسالة عربية قصيرة توضّح المشكلة.

أبقي ترتيب المهام كما أُضيفت، وأستبعد التصنيفات والمواعيد والتأكيد قبل الحذف في هذا الاختبار. معيار النجاح: إضافة مهمة، إكمالها، إغلاق التطبيق وإعادة فتحه، ثم التأكد من بقائها وحذفها بنجاح.

### Gemini (google/gemini-4-carbon)

أهلاً بكم جميعاً يا رفاق، وأهلاً بصاحب الطاولة. سعيد بوجودي معكم (Claude، ChatGPT، وGrok) في هذا النقاش.

بصفتي "محلل البيانات" على هذه الطاولة، حتى في أبسط التطبيقات وأول اختبار للبناء، أرى أن المستخدم لا يكتب مهامه لمجرد تفريغها، بل يشعر بالإنجاز عندما يرى **مؤشرات التقدم (KPIs)** تتحرك أمامه. وبما أن الشرط الأساسي هو "البساطة التامة" واستخدام `shared_preferences` فقط دون تعقيد، إليكم خطتي المقترحة من زاوية البيانات وتصويرها البصري:

### 1. هيكلة البيانات والتخزين (Data Structure)
لضمان نظافة البيانات وسهولة حساب المقاييس دون استخدام حزم خارجية إضافية، نقترح نموذج بيانات (Model) بسيط جداً لكل مهمة يُحول إلى JSON نصي باستخدام مكتبة `dart:convert` المدمجة، ويُحفظ كقائمة نصوص `List<String>` في `shared_preferences`:
```dart
class Task {
  String id; // الطابع الزمني لإنشاء المهمة (ممتاز للترتيب الفريد)
  String title;
  bool isCompleted;
  // دوال toJson و fromJson بسيطة
}
```

### 2. مقاييس الأداء المصغّرة (Micro-KPIs)
تطبيق المهام هو في جوهره أداة لقياس الإنتاجية الشخصية. أقترح حساب 3 أرقام بسيطة برمجياً وعرضها لحظياً مع كل تغيير (`setState`):
* **إجمالي المهام (Total):** حجم القائمة `tasks.length`.
* **المهام المنجزة (Completed):** `tasks.where((t) => t.isCompleted).length`.
* **نسبة الإنجاز (Completion Rate):** `total == 0 ? 0.0 : completed / total`.

### 3. التصوير البصري للبيانات (Data Visualization) بتصميم Material 3
بدلاً من شاشة جافة تعرض نصوصاً فقط، يمكننا استغلال مكونات Material 3 القياسية لتمثيل هذه الأرقام بصرياً في أعلى الشاشة الوحيدة دون أي ثقل برمجي:
* **بطاقة ملخص الإنجاز (Summary Card):** نضع في أعلى القائمة `Card` أنيقة وهادئة تحتوي على نص واضح باللغة العربية (مثلاً: *"أنجزت 3 من أصل 5 مهام"*).
* **مؤشر التقدم البصري:** تحت النص مباشرة داخل البطاقة، نضع `LinearProgressIndicator` يأخذ قيمته من (نسبة الإنجاز) مع زوايا دائرية (`borderRadius`). رؤيته يمتلئ تدريجياً تعطي المستخدم دفعة تحفيزية فورية وبأقل من 5 أسطر برمجية!
* **حالة انعدام البيانات (Zero-Data State):** إذا كانت القائمة فارغة (`total == 0`)، نخفي بطاقة الإحصائيات ونعرض في المنتصف أيقونة لطيفة مع نص: *"لا توجد مهام حالياً، أضف مهمتك الأولى لبدء قياس إنجازك"*.

### 4. تجربة المستخدم والتفاعل (RTL & Actions)
* فرض اتجاه النص من اليمين لليسار `Directionality(textDirection: TextDirection.rtl)` لدعم العربية بشكل أصيل.
* كل مهمة تُعرض في `ListTile` تحتوي على `Checkbox` للإنجاز (مع شطب النص `TextDecoration.lineThrough` لتأكيد التغيير بصرياً)، وزر حذف `IconButton` واضح، أو ميزة السحب للحذف `Dismissible` لزيادة نظافة الواجهة.

بهذه الخطة، نلتزم حرفياً بشرط البساطة المطلقة للاختبار الأول، ونحول التطبيق من مجرد "مفكرة نصوص" إلى "لوحة إنجاز مصغرة" مريحة للعين. 

بانتظار سماع زوايا نظركم يا شباب، خصوصاً فيما يتعلق بتنظيم الكود وتفاصيل الواجهة!

### Grok (x-ai/grok-4.7)

أبدأ من قيد المستخدم نفسه: `shared_preferences` فقط، وشاشة واحدة، وأول اختبار بناء. لا أوسّع النطاق.

**ما أقبله كما هو**
- حالة محلية بـ `StatefulWidget` و`setState`. لا Provider ولا Riverpod؛ أي طبقة إضافية هنا مخاطرة على أول بناء بلا فائدة.
- نموذج مهمة بسيط: `id` (millis أو UUID نصي)، `title`، `done`.
- التخزين: مفتاح واحد `tasks` وقيمة JSON (`jsonEncode` / `jsonDecode` من `dart:convert`). الحزمة لا تخزّن قوائم كائنات.

**اعتراض وبديل**
`shared_preferences` سيئة لقائمة متنامية: كتابة كاملة عند كل نقرة، وفساد JSON يمسح القائمة. البديل داخل القيد وليس خارجه: دالة `load()` تبتلع الخطأ وتعيد `[]`، ودالة `save()` تُستدعى بعد كل تغيير ناجح فقط. لا ملف ولا قاعدة بيانات.

**عربية وMaterial 3**
- `MaterialApp` مع `locale: Locale('ar')` و`Directionality` عبر `localizationsDelegates` الأساسية، أو على الأقل `builder` يلف الشجرة بـ `Directionality(textDirection: TextDirection.rtl)`.
- `ThemeData(useMaterial3: true)` ولون واحد. لا ثيم فاتح/داكن في هذا الاختبار.
- الحقول والأزرار بالعربية: «مهمة جديدة»، «إضافة»، «لا مهام بعد».

**سلوك الواجهة**
- `TextField` + زر إضافة. العنوان الفارغ أو المسافات فقط: لا تُضاف، و`SnackBar` قصير.
- `Checkbox` أو `IconButton` للتعليم كمكتملة، مع `TextDecoration.lineThrough`.
- حذف بـ `IconButton`، بدون تأكيد؛ التأكيد يبطئ الاختبار الأول.
- `ListView.builder` داخل `Scaffold` واحد. لا مسارات ولا شاشات.

**ملفات**
`main.dart` يكفي: النموذج، التحميل/الحفظ، والواجهة. تقسيم الملفات ترف هنا.

# موقفي في الجولة 2: حسم النطاق

سأحسم كل نقطة مفتوحة بمعيار واحد: هل تُضيف خطراً على أول بناء، أو تتجاوز ما طلبه المستخدم حرفياً؟

## القرارات

1. **بطاقة التقدم (Gemini):** أرفضها في هذا الاختبار. فكرتك جميلة يا Gemini، لكن المستخدم طلب أربع وظائف فقط: إضافة وإكمال وحذف وحفظ. البطاقة ميزة خامسة لم تُطلب، وتزيد الكود وحالات الاختبار. تصلح لجولة لاحقة بعد نجاح البناء.
2. **التخزين:** `setString` مع JSON واحد. موافق يا Grok على المفتاح الواحد. أفضّله على `setStringList` لأن الكتابة ذرّية، وتبقى القراءة والكتابة سطراً واحداً لكل منهما.
3. **الحذف:** `IconButton` صريح بلا `Dismissible` وبلا تأكيد. السحب يضيف سلوكاً يتطلب `key` ومعالجة اتجاهات في RTL، وهذا مصدر التباس بلا فائدة.
4. **التراجع:** أسحب اقتراحي السابق. `SnackBar` مع "تراجع" يعني منطق إعادة إدراج في الموضع الأصلي، وهو زائد. الحذف مباشر.
5. **الأخطاء:** أقبل الحد الأدنى: `try/catch` حول `_load` فقط، فإذا فشلت القراءة أو فسد JSON نبدأ بقائمة فارغة. موافق يا Grok. أما رسائل الخطأ العربية على الكتابة وتسلسل الحفظ الذي اقترحه ChatGPT فأراه زائداً هنا، لأن `setState` متزامن والحفظ يُستدعى بعده مباشرة، والكتابة الأحدث تصل أخيراً عملياً. نقطة ChatGPT الوجيهة هي منع التعديل قبل انتهاء التحميل، وهي مغطاة بمؤشر `_loading` الذي يخفي الواجهة.
6. **النص الفارغ:** تجاهل صامت بعد `trim()`. لا `SnackBar`، فالزر الفارغ لا يضر المستخدم.
7. **التعريب:** `Directionality` عبر `builder` في `MaterialApp`، دون `flutter_localizations`، لأنها حزمة SDK لكنها تتطلب تعديل `pubspec.yaml`، وهذا خطر على أول بناء. وأسمي هذا خياراً مقصوداً لا خرقاً للشرط.
8. **الإكمال:** `CheckboxListTile` كما اقترح Grok، فهو أقل كوداً. زر الحذف يوضع في `secondary`.

## الهيكل النهائي المتفق عليه

```dart
import 'dart:convert';
import 'package:flutter/material.dart';
import 'package:shared_preferences/shared_preferences.dart';

class Task {
  Task(this.id, this.title, [this.done = false]);
  final String id;
  final String title;
  bool done;
  Map<String, dynamic> toJson() => {'id': id, 'title': title, 'done': done};
  factory Task.fromJson(Map<String, dynamic> j) =>
      Task(j['id'], j['title'], j['done'] ?? false);
}
```

وفي الحالة:

```dart
Future<void> _load() async {
  try {
    final p = await SharedPreferences.getInstance();
    final raw = p.getString('tasks');
    if (raw != null) {
      _tasks = (jsonDecode(raw) as List)
          .map((e) => Task.fromJson(e as Map<String, dynamic>))
          .toList();
    }
  } catch (_) {
    _tasks = [];
  }
  if (mounted) setState(() => _loading = false);
}

Future<void> _save() async {
  final p = await SharedPreferences.getInstance();
  await p.setString('tasks', jsonEncode(_tasks.map((t) => t.toJson()).toList()));
}
```

وفي `build` نعرض `CircularProgressIndicator` إذا `_loading`، وإلا حقل الإدخال مع `ListView.builder`، أو "لا مهام بعد" إن كانت القائمة فارغة.

## ما أطلبه من الطاولة

إذا وافقتم يا ChatGPT وGemini وGrok على هذه النقاط الثماني، يكتب رئيس الجلسة `main.dart` الكامل مباشرة. وأقترح أن نؤجل بطاقة التقدم إلى "الخطوة التالية" ونذكرها للمستخدم كتحسين اختياري.

### ChatGPT (openai/gpt-6.1-sol)

Claude، أوافق على حسم النطاق: **لا بطاقة تقدم، و`setString` لقائمة JSON واحدة، وحذف بزر صريح بلا تراجع، وتجاهل الإدخال الفارغ بعد `trim()`**. Gemini، أقترح تأجيل الملخص تماماً حتى ينجح اختبار البناء. Grok، متفق معك على ملف واحد وحالة محلية فقط.

يبقى تصحيحان صغيران قبل اعتماد النسخة:

- **الحفظ غير متزامن:** تزامن `setState` لا يضمن ترتيب اكتمال الكتابات. كذلك `setString` لا يمنحنا ضماناً عاماً للكتابة الذرّية أو الاستدامة. أبقي تسلسل الحفظ، مع التقاط JSON وقت كل تعديل ومعالجة فشل كل عملية حتى لا تتوقف السلسلة. هذا منطق داخلي قصير، لا ميزة إضافية.
- **لا نبتلع أخطاء التخزين بصمت:** يكفي `SnackBar` عربي عند فشل القراءة أو الحفظ؛ وإلا قد يظن المستخدم أن مهامه محفوظة وهي ليست كذلك. عند فشل القراءة نقول «تعذّر تحميل المهام المحفوظة»، ولا نحفظ القائمة الفارغة تلقائياً.

**التعريب:** أوافق على `Directionality` عبر `builder` فقط، **دون ضبط `locale: Locale('ar')`** ما دمنا لا نضيف مفوّضات التعريب العربية. نصوصنا عربية والاتجاه RTL، لكن لا ندّعي تعريب أدوات Flutter الافتراضية.

ولرئيس الجلسة ثلاث تفاصيل تنفيذية أخيرة:
1. حجب أدوات التعديل حتى انتهاء التحميل، وفحص `mounted` بعد الانتظار.
2. استدعاء `dispose()` لمتحكم حقل النص، ودعم الإضافة من لوحة المفاتيح.
3. إعطاء زر الحذف `tooltip: 'حذف المهمة'`، والسماح لعنوان المهمة بالالتفاف.

بهذه التعديلات أوافق على الخطة المشتركة، ولا أرى حاجة لأي مكوّن أو ميزة أخرى في النسخة الأولى.

### Gemini (google/gemini-4-carbon)

شكراً لكم يا شباب على هذا التركيز العالي. بصفتي محلل البيانات، لغة الأرقام والمخاطر عندي واضحة: **نجاح البناء الأول بنسبة 100% أهم من أي ميزة إضافية**. لذلك، إليكم موقفي الحاسم للوصول إلى اتفاق نهائي:

1. **بطاقة التقدم والمقاييس (KPIs):** أتفق تماماً معك يا **Claude** ويا **ChatGPT**. أسحب اقتراح البطاقة وشريط التقدم من الكود الأساسي التزاماً حرفياً بشرط "بسيط جداً لأول اختبار"، وأؤيد فكرة Claude الذكية بالإشارة إليها في نهاية ردنا كـ "خطوة تالية مقترحة" بعد نجاح البناء.
   *(ملاحظة بسيطة من زاوية البيانات: إذا رغب رئيس الجلسة، يمكن عرض العدد في عنوان الشاشة مثل `مهامي (3)` بدون أي كود إضافي، وإن رأيتم إبقاءها `مهامي` فقط فأنا موافق أيضاً).*

2. **صيغة التخزين:** أوافق **Grok** و**Claude** على استخدام `setString` لحفظ القائمة كاملة كـ JSON واحد تحت مفتاح `tasks`، وأتنازل عن `setStringList`. التعامل مع كتلة نصية واحدة أنظف في القراءة والكتابة (`jsonEncode`/`jsonDecode`).

3. **طريقة الحذف والتراجع والنص الفارغ:** 
   * موافق بالإجماع على الحذف المباشر بزر `IconButton` صريح بدون `Dismissible` وبدون `SnackBar` للتراجع.
   * موافق على التجاهل الصامت للنص الفارغ بعد `trim()`.
   * أؤيد استخدام `ListTile` عادية فيها `leading: Checkbox` و `trailing: IconButton` بدلاً من `CheckboxListTile`؛ لأن `CheckboxListTile` تضع المربع في اليسار (trailing) افتراضياً وتستخدم `secondary` للطرف الآخر، مما قد يربك الترتيب البصري في الواجهة العربية (نريد المربع في اليمين، النص في الوسط، والحذف في اليسار بوضوح).

4. **التعريب:** أتفق مع تصحيح **ChatGPT** الدقيق جداً: نكتفي بـ `Directionality(textDirection: TextDirection.rtl)` داخل `builder` في `MaterialApp`، **وبدون** وضع `locale: Locale('ar')` طالما لم نضف حزمة `flutter_localizations` في `pubspec.yaml`، وذلك لتجنب أي تحذيرات أو أخطاء غير متوقعة في أول بناء.

5. **حسم الخلاف بين Claude و ChatGPT حول (معالجة الأخطاء وتسلسل الحفظ):**
   هنا أميل لجانب البساطة الذي طرحه **Claude** و**Grok** مع لمسة أمان واحدة:
   * **أعارض تسلسل عمليات الحفظ (Queueing):** يا **ChatGPT**، في تطبيق مهام محلي صغير يعتمد على `shared_preferences` (التي تكتب في كاش الذاكرة أولاً بشكل شبه لحظي)، بناء طابور تسلسل (Future chaining) لحفظ النصوص هو هندسة مفرطة (Over-engineering) لاختبار بناء أول. استدعاء `_save()` البسيط مع حفظ نسخة SharedPreferences في متغير بالذاكرة عند البداية يكفي جداً.
   * **أوافق جزئياً على تنبيه الخطأ:** في `_load()` و `_save()` نضع `try/catch`. إذا فشل التحميل نبدأ بقائمة فارغة، وإذا أردنا إرضاء نقطة ChatGPT بأقل كود ممكن، سطر واحد `ScaffoldMessenger` يعرض رسالة خطأ في الـ `catch` لا يضر ولا يعقد الكود، وإن حذفه رئيس الجلسة للتبسيط فلا مانع لدي.

خلاصة موقفي: أنا متفق معكم بالكامل على الهيكل الموحد لملف `main.dart`، والكرة الآن عند **Grok** ليحسم صوته الأخير ثم يتفضل رئيس الجلسة بكتابة الكود النهائي!

### Grok (x-ai/grok-4.7)

Claude، أوافق على رفض البطاقة وعلى `setString` تحت مفتاح `tasks`، وعلى حذف مباشر بزر بلا تراجع، وعلى تجاهل النص الفارغ بعد `trim()`. ChatGPT، نقطة «لا تحفظ قائمة فارغة إذا فشل التحميل» صحيحة وأبقيها. Gemini، أسحب معك أي عدّاد في العنوان؛ «مهامي» فقط.

**اعتراض وبديل — ترتيب المربع**
يا Gemini، افتراض أن `CheckboxListTile` يضع المربع يساراً في واجهة عربية غير دقيق. مع `Directionality` يكون `ListTileControlAffinity.leading` على يمين الشاشة. هذا أقل كوداً من `ListTile` مخصّصة، ويُبقي الحذف في `secondary` على اليسار. لا نغيّر المكوّن بسبب اتجاه افتراضي LTR.

**اعتراض وبديل — طابور الحفظ ورسائل الخطأ**
يا ChatGPT، تسلسل كامل هندسة زائدة، لكن تجاهل السباق أيضاً ثغرة: كتابتان متداخلتان قد تُنهي القديمة بعد الجديدة. البديل ثلاثة أسطر لا طابور معماري: نلتقط JSON لحظة التعديل ونربطه بـ `_pending`:

```dart
_pending = _pending.then((_) => prefs.setString('tasks', snapshot));
```

يا Claude، `SnackBar` من داخل `_load` قبل تركيب `Scaffold` قد يرمي استثناءً ويفشل أول بناء. لذلك لا رسالة في هذه النسخة: فشل القراءة يعني `[]` دون كتابة فوق التخزين، وفشل الكتابة يُبتلع داخل السلسلة حتى لا تنقطع. المستخدم قد لا يعرف أن الحفظ فشل، وهذا الخطر المقبول في اختبار أول؛ الرسالة تؤجَّل مع بطاقة Gemini.

**ما يُقفل النطاق**
`Directionality` في `builder` فقط، بلا `locale` وبلا `flutter_localizations`. حجب الإدخال حتى ينتهي التحميل، و`mounted` بعد كل `await`، و`dispose` للمتحكم، و`onSubmitted` للإضافة. هذا تصحيح لا ميزة.

بهذا أحسم معكم: ملف واحد، الحالة المحلية، JSON واحد، زر حذف، بلا تراجع وبلا تنبيه فراغ وبلا شريط تقدم. رئيس الجلسة يستطيع كتابة `main.dart` النهائي على هذا الأساس.

> **رئيس الجلسة:** 🔎 **فلتر الإجماع:** دقّقت الحل ولم أجد خطأً جوهرياً.

FILE: lib/main.dart
```dart
import 'dart:convert';

import 'package:flutter/material.dart';
import 'package:flutter_localizations/flutter_localizations.dart';
import 'package:shared_preferences/shared_preferences.dart';

void main() => runApp(const TodoApp());

/// نموذج المهمة.
class Task {
  Task({required this.id, required this.title, this.done = false});

  final String id;
  final String title;
  bool done;

  Map<String, dynamic> toJson() => {'id': id, 'title': title, 'done': done};

  factory Task.fromJson(Map<String, dynamic> json) => Task(
        id: json['id'] as String,
        title: json['title'] as String,
        done: json['done'] as bool? ?? false,
      );
}

class TodoApp extends StatelessWidget {
  const TodoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'مهامي',
      debugShowCheckedModeBanner: false,
      // اللغة العربية تضبط اتجاه RTL تلقائياً.
      locale: const Locale('ar'),
      supportedLocales: const [Locale('ar')],
      localizationsDelegates: const [
        GlobalMaterialLocalizations.delegate,
        GlobalWidgetsLocalizations.delegate,
        GlobalCupertinoLocalizations.delegate,
      ],
      theme: ThemeData(
        useMaterial3: true,
        colorSchemeSeed: Colors.teal,
      ),
      home: const TodoPage(),
    );
  }
}

class TodoPage extends StatefulWidget {
  const TodoPage({super.key});

  @override
  State<TodoPage> createState() => _TodoPageState();
}

class _TodoPageState extends State<TodoPage> {
  static const String _storageKey = 'tasks';

  final TextEditingController _controller = TextEditingController();

  List<Task> _tasks = <Task>[];
  bool _loading = true;
  SharedPreferences? _prefs;

  // سلسلة الحفظ: تضمن أن تُكتب النسخ بترتيب التعديلات.
  Future<void> _pending = Future<void>.value();

  @override
  void initState() {
    super.initState();
    _load();
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  Future<void> _load() async {
    var tasks = <Task>[];
    var failed = false;
    try {
      final prefs = await SharedPreferences.getInstance();
      _prefs = prefs;
      final raw = prefs.getString(_storageKey);
      if (raw != null) {
        tasks = (jsonDecode(raw) as List)
            .map((e) => Task.fromJson(Map<String, dynamic>.from(e as Map)))
            .toList();
      }
    } catch (_) {
      // عند الفشل نبدأ بقائمة فارغة دون الكتابة فوق التخزين.
      tasks = <Task>[];
      failed = true;
    }
    if (!mounted) return;
    setState(() {
      _tasks = tasks;
      _loading = false;
    });
    if (failed) _notify('تعذّر تحميل المهام المحفوظة');
  }

  void _save() {
    final prefs = _prefs;
    if (prefs == null) {
      _notify('تعذّر حفظ المهام');
      return;
    }
    // نلتقط نسخة JSON لحظة التعديل.
    final snapshot = jsonEncode(_tasks.map((t) => t.toJson()).toList());
    _pending = _pending.then((_) async {
      try {
        final ok = await prefs.setString(_storageKey, snapshot);
        if (!ok) _notify('تعذّر حفظ المهام');
      } catch (_) {
        _notify('تعذّر حفظ المهام');
      }
    });
  }

  void _notify(String message) {
    if (!mounted) return;
    ScaffoldMessenger.of(context)
      ..hideCurrentSnackBar()
      ..showSnackBar(SnackBar(content: Text(message)));
  }

  void _add() {
    final title = _controller.text.trim();
    if (title.isEmpty) return;
    setState(() {
      _tasks.add(
        Task(
          id: DateTime.now().microsecondsSinceEpoch.toString(),
          title: title,
        ),
      );
    });
    _controller.clear();
    _save();
  }

  void _toggle(Task task, bool value) {
    setState(() => task.done = value);
    _save();
  }

  void _remove(Task task) {
    setState(() => _tasks.removeWhere((t) => t.id == task.id));
    _save();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('مهامي'),
        centerTitle: true,
      ),
      body: SafeArea(
        child: _loading
            ? const Center(child: CircularProgressIndicator())
            : Column(
                children: [
                  _buildInput(),
                  Expanded(
                    child: _tasks.isEmpty ? _buildEmpty() : _buildList(),
                  ),
                ],
              ),
      ),
    );
  }

  Widget _buildInput() {
    return Padding(
      padding: const EdgeInsets.fromLTRB(16, 12, 16, 8),
      child: Row(
        children: [
          Expanded(
            child: TextField(
              controller: _controller,
              textInputAction: TextInputAction.done,
              onSubmitted: (_) => _add(),
              decoration: const InputDecoration(
                hintText: 'أضف مهمة جديدة',
                border: OutlineInputBorder(),
              ),
            ),
          ),
          const SizedBox(width: 12),
          FilledButton.icon(
            onPressed: _add,
            icon: const Icon(Icons.add),
            label: const Text('إضافة'),
          ),
        ],
      ),
    );
  }

  Widget _buildEmpty() {
    final scheme = Theme.of(context).colorScheme;
    return Center(
      child: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          Icon(Icons.checklist_rounded, size: 64, color: scheme.outline),
          const SizedBox(height: 12),
          Text(
            'لا توجد مهام بعد',
            style: Theme.of(context)
                .textTheme
                .titleMedium
                ?.copyWith(color: scheme.outline),
          ),
        ],
      ),
    );
  }

  Widget _buildList() {
    final scheme = Theme.of(context).colorScheme;
    return ListView.builder(
      padding: const EdgeInsets.only(bottom: 16),
      itemCount: _tasks.length,
      itemBuilder: (context, index) {
        final task = _tasks[index];
        return CheckboxListTile(
          key: ValueKey<String>(task.id),
          value: task.done,
          onChanged: (value) => _toggle(task, value ?? false),
          // في الواجهة العربية يظهر المربع على اليمين.
          controlAffinity: ListTileControlAffinity.leading,
          title: Text(
            task.title,
            style: TextStyle(
              decoration: task.done ? TextDecoration.lineThrough : null,
              color: task.done ? scheme.outline : null,
            ),
          ),
          secondary: IconButton(
            tooltip: 'حذف المهمة',
            icon: const Icon(Icons.delete_outline),
            onPressed: () => _remove(task),
          ),
        );
      },
    );
  }
}
```

**ما يفعله التطبيق:**
- **الإضافة:** من زر «إضافة» أو من زر لوحة المفاتيح، ويُتجاهل النص الفارغ بصمت.
- **الإكمال:** مربع اختيار على اليمين، ويُشطب نص المهمة المكتملة ويخفت لونه.
- **الحذف:** زر مباشر على اليسار، بلا تأكيد ولا تراجع.
- **الحفظ:** تُحفظ القائمة تلقائياً بعد كل تعديل وتُحمَّل عند فتح التطبيق.

## نقاط الخلاف المتبقية

حُسمت بالإجماع: رفض بطاقة التقدم، و`setString` بنص JSON واحد، والحذف بزر صريح بلا تراجع، وتجاهل النص الفارغ. بقيت أربع نقاط رجّحتُ فيها:

1. **التعريب:** اتفق الأعضاء على `Directionality` وحده دون `flutter_localizations` ودون `locale`. خالفتُ هذا الاتفاق لأن مواصفات المخرج المطلوبة لهذه الجلسة تشترط `flutter_localizations` مع `locale: ar`. وهي جزء من Flutter SDK نفسه لا حزمة خارجية، فيبقى `shared_preferences` الحزمة الخارجية الوحيدة. إن أردت الالتزام الحرفي بطلبك، احذف سطري `flutter_localizations` من `pubspec.yaml` واستيرادها وخصائص `locale` و`supportedLocales` و`localizationsDelegates`، ثم أضف إلى `MaterialApp` السطر التالي:
   ```dart
   builder: (context, child) => Directionality(textDirection: TextDirection.rtl, child: child!),
   ```

2. **ترتيب الحفظ:** رأى Claude وGemini أن استدعاء الحفظ مباشرة يكفي، وطالب ChatGPT بتسلسل الكتابات. رجّحتُ صيغة Grok المختصرة (ربط كل كتابة بـ `_pending`)، لأنها تمنع وصول كتابة قديمة بعد الأحدث بثلاثة أسطر فقط.

3. **رسائل أخطاء التخزين:** رأى Claude وGrok ابتلاع الخطأ بصمت، وطالب ChatGPT برسالة عربية، وقبلها Gemini إن كانت قصيرة. رجّحتُ رأي ChatGPT، لأن الصمت قد يوهمك بأن مهامك محفوظة وهي ليست كذلك. أما اعتراض Grok بأن `SnackBar` قد يرمي استثناءً قبل تركيب `Scaffold` فلا ينطبق هنا: الرسالة تُعرض بعد `await` وفحص `mounted`، وتعتمد على `ScaffoldMessenger` الذي يوفّره `MaterialApp`.

4. **مكوّن عنصر القائمة:** فضّل Gemini `ListTile` مخصّصة خشية ظهور المربع على اليسار. رجّحتُ `CheckboxListTile` كما قال Grok، لأن `ListTileControlAffinity.leading` يضع المربع على اليمين في اتجاه RTL، وبكود أقل.
